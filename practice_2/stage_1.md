# Практическая работа №2. Этап 1

**Дисциплина:** Конфигурационное управление. **Вариант:** 22.

## Цель и требования

Создать минимальное CLI-приложение для настройки будущего инструмента
визуализации зависимостей Java Maven. По странице 71 методички параметры
задаются опциями командной строки: имя пакета, источник репозитория,
тестовый режим и режим ASCII-дерева. На первом этапе требуется вывести
все настройки в формате ключ—значение и обработать ошибки каждого параметра.

## Реализация

Перед добавлением работы изучены структура репозитория и история коммитов.
Последний исходный коммит — `898a4c4`, этап 3 эмулятора командной оболочки.
Новая работа размещена в `practice_2/` с собственными исходниками, тестами
и скриптом запуска. В корневой README добавлена ссылка.
Исходники, тесты, скрипты и отчёт предыдущей работы сохранены.

Программа написана на Python со стандартной библиотекой `argparse`.
Обязательны `--package` и `--repository`. Флаги `--test-repository`
и `--ascii-tree` по умолчанию выключены и не принимают значений.
Для Maven выбран формат `groupId:artifactId[:version]`, для тестового
режима — одна большая латинская буква. Эти правила проверяются до вывода.

Основная часть программы:

```python
config = parser.parse_args(argv)
try:
    validate_package(config.package, config.test_repository)
    if config.test_repository:
        validate_file(config.repository)
    else:
        validate_url(config.repository)
except ValueError as error:
    parser.error(str(error))
print(f"package={config.package}")
print(f"repository={config.repository}")
print(f"test_repository={str(config.test_repository).lower()}")
print(f"ascii_tree={str(config.ascii_tree).lower()}")
```

Проверяется синтаксис HTTP(S) URL, в том числе имя сервера и порт.
В тестовом режиме проверяются существование файла и возможность его открыть.
URL вместо файла и файл без тестового режима вызывают ошибку.
Неверные аргументы завершают программу с кодом 2, сообщение попадает в stderr.
Сетевые запросы, чтение зависимостей и построение графа отсутствуют.

## Проверка

Из корня репозитория выполнена команда:

```sh
python3 -m unittest discover -s practice_2/tests -v
```

Пройдены 15 тестовых методов с отдельными проверками входных значений.
Проверены оба источника, состояния флагов, обязательные значения,
некорректные координаты, URL и пути, несогласованный режим и неверные флаги.
Также проверены справка и запуск из другого каталога с пробелом в имени файла.
Ошибка доступа к файлу воспроизводится через `unittest.mock`, остальные
проверки CLI запускают программу отдельным процессом.

Полный вывод тестов и реальные демонстрационные команды с кодами возврата
приведены в [протоколе проверки](tests/RESULTS.md).

## Этап 1. Минимальный прототип с конфигурацией

**Цель:** создать CLI-приложение для настройки инструмента
визуализации зависимостей Java Maven.

### Требования

По странице 71 методички параметры задаются опциями командной строки:
имя пакета, URL репозитория или путь к тестовому файлу, тестовый режим
и режим ASCII-дерева. На первом этапе нужно вывести все четыре настройки
в формате ключ—значение и продемонстрировать ошибки каждого параметра.

### Реализация

Работа находится в отдельном каталоге `practice-02-variant-22`.
Перед добавлением изучены структура и история репозитория.
Файлы предыдущей работы с эмулятором сохранены.

Используются Python и стандартная библиотека `argparse`.
Точка входа — `src/main.py`, разбор и проверка аргументов вынесены
в `src/depgraph/config.py`, вывод — в `src/depgraph/cli.py`.

Обязательны `--package` и `--repository`. Флаги `--test-repository`
и `--ascii-tree` по умолчанию выключены и не принимают значений.
Для Maven используется формат `groupId:artifactId[:version]`,
для тестового режима — одна большая латинская буква.

Основная функция CLI:

```python
def main(argv=None):
    """Вывести четыре проверенные настройки в формате ключ=значение."""
    config = parse_args(argv)
    print(f"package={config.package}")
    print(f"repository={config.repository}")
    print(f"test_repository={str(config.test_repository).lower()}")
    print(f"ascii_tree={str(config.ascii_tree).lower()}")
    return 0
```

До вывода проверяются имя пакета и выбранный тип источника.
У HTTP(S) URL проверяются сервер, порт и синтаксис.
В тестовом режиме проверяются существование файла и возможность его открыть.
URL вместо файла и путь без тестового режима вызывают ошибку.
Ошибки аргументов выводятся в stderr с кодом 2, успешный запуск возвращает 0.

### Проверка

Все команды выполнены из каталога практики:

```bash
bash run.sh --package junit:junit:4.13.2 --repository https://repo.maven.apache.org/maven2/ --ascii-tree
```

```text
package=junit:junit:4.13.2
repository=https://repo.maven.apache.org/maven2/
test_repository=false
ascii_tree=true
```

```bash
bash run.sh --package A --repository examples/repository.txt --test-repository
python3 -B -m unittest discover -s tests -v
```

Пройдены 15 тестовых методов с отдельными проверками входных значений.
Проверены оба источника, состояния флагов, отсутствие обязательных значений,
неверные имена, URL и пути, несогласованный режим и неправильные флаги.
Также проверены справка и запуск из другого каталога с пробелом в имени файла.
Ошибка доступа к файлу воспроизводится через `unittest.mock`.
Остальные проверки CLI запускают приложение отдельным процессом.

Полные результаты и сообщения ошибок сохранены в [протоколе](tests/RESULTS.md).
